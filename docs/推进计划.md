## 六、出片提速：只做对瓶颈的那一刀

| 帧怎么传 | 1080p60 全片 | 判据 |
|:--|:--|:--|
| `--frame raw`（原始 RGBA 8.3 MB/帧） | 8.8 fps / 24.5 分钟 | `send` 受 ~90 MB/s 的 WebSocket 带宽限制 |
| `--frame jpeg --q 0.95`（0.48 MB/帧） | 22.6 fps / 9.6 分钟 | 那 28 ms 主体是浏览器每帧一次 JPEG 编码，不是字节 |
| **`--frame h264`（页面内硬编，默认）** | **86–125 fps / 约 2.5 分钟** | 编码器在页面里，ffmpeg 只 `-c copy`；`render 1 read 0.1 send 4`；成片 682.7 MB |

三条不要做：降分辨率（已定 1080p 下限）、降 JPEG 质量（省字节不省编码时间）、给 x264 加线程（纯编码侧 110 fps，本来不是瓶颈）。

出口数据：`node tools/probe_webcodecs.mjs`（探测硬件编码器）+ `out\_lib\render2/3/4.log`（三档对照）；根因与三次翻车见 `说明\踩坑与经验.md` 四节。
