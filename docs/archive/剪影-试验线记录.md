> 从 `二次创作\说明\剪影规格.md` 拆出（2026-11-21）：这里只有**已结案的试验过程**（SVG 矢量化、Live2D 顶剪影、七阶、原生立绘、真剪影、层次配方的实测）。规格单本体仍在原文件。

## 七、SVG 路线：实测结论（2026-11-16 第一轮）→ **2026-11-17 结案：不做**

> **结案**：阁下判定「SVG 是明确无法做到有效输出的思路」，本线就此关闭，不再作为待办、不再等矢量源。
> 三条硬理由：① 把现有位图转成 SVG 只是矢量化，不增加任何信息；② 真正的矢量源（画师按 path 画）不存在，
> 拿自己描的 SVG 去验证是循环论证；③ 想让引擎直接吃矢量，得对路径做布尔运算（`exact` 版要"某墨减去上一墨"），
> Path2D 做不到，改三条互斥路径等于重写美术层——投入产出比在这一步已经判死。
> 下文是那一轮的实测记录，**只作留档**：里面的命令、告警与「如果画师按 SVG 交付」五条，都不再执行。
>
> **`assets/character_svg/` 的去留（2026-11-20 已执行）**：已连同生成器 `tools/raster_to_svg.mjs` 一起清出仓库（8 文件 1.86 MB + 5 KB）。删前核过：代码侧没有任何加载路径引用它，命中的三处都在工具里——生成器的默认输出目录、`art_dims.mjs` 注释里的例子、生成器分步说明。删后 `art_dims.mjs` 的 `--svg` 开关仍在，将来画师真交付矢量时直接指过去即可。

**结论先写在前面：管线现在能吃 SVG、也能吃任意分辨率的大图（坐标基准已参数化并验证）；但把现有八张位图转成 SVG 没有可见收益——矢量化不增加信息。SVG 真正的价值在「画师按矢量交付」这件事上，不在「把 PNG 转一遍」。**

### 已打通的部分

- `loadArt` 支持可选 `cfg.paths.artSvg`（或启动参数 `?artsvg=`、导出参数 `--artsvg`）：按 `<目录>/<name>.svg` 取图，取不到就逐张回落 PNG 并 warn 一次。`src/engine/art.js`。
- `export/server.mjs` 的 MIME 表补了 `.svg`（原来没有 → 浏览器按 binary 拒解码，静默回落 PNG，这一坑实测踩过：两张 4K 静帧的 SHA256 完全相同）。
- `tools/raster_to_svg.mjs`（**2026-11-20 已删**，此条留档）：把三墨 PNG 矢量化成 `<name>.svg`，用的是引擎自己的分离和描线代码（`_prepareInk` + `trace.js` 的 `outline`/`smoothPath`），所以边界与片内一致；输出三块**累进版**（cream → orange → black，无孔洞、不依赖 fill-rule），单张 170–350 KB。
- SVG 只写 `viewBox` 时 Chrome 回落成 113×150 的固有尺寸，整张作废。现在 `loadArt` 会自动从 `viewBox` 补 `width`/`height`，同时检查两件事并 warn：长宽比偏离设计基准 >2%（片子里每处裁切都会被拉扁）、解码尺寸不足设计基准 1.5×（特写拿不到矢量的好处）。
- `tools/art_dims.mjs`（新增）：量一遍八张进管线时的真实源尺寸、设计基准、`sx`/`sy` 换算系数与长宽比偏差，并把上面的告警原样打出来。换图前后都该跑一遍。

### 实测数据（3840×2160 静帧，同一秒 PNG 版 vs SVG 版）

| 对比 | 结果 |
| --- | --- |
| `f_eye` 特写（166.5 秒），SVG 烘焙 **1254×1254**（与源同尺寸） | PSNR 37.4 dB；1:1 像素切片并排看不出差别 |
| `f_eye` 特写（166.5 秒），SVG 烘焙 **3000×3000**（放大 2.4×） | PSNR 42.5 dB，边缘略顺滑但**没有新增细节** |
| `f_reach` 手部特写（170.19 秒），SVG 烘焙 **2250×3000**，坐标基准参数化**之前** | 构图明显错位，PSNR **11.16 dB** |
| 同上，参数化**之后** | **38.5 dB**，并排看不出错位（`out/ab4k_png_s.png` vs `out/ab4k_svg_s.png`） |

第三、四行说明得很清楚：错位不是 SVG 的毛病，是源尺寸一变、场景里 1086×1448 的基准没跟着变。基准收进 `art` 内部之后，同一条边放大到 2.07× 仍然对得齐。

「位图矢量化不增加信息」这一条没变：同尺寸只是把同一条边重画一遍（37.4 dB），放大尺寸只是把同一条边画细（42.5 dB），细节不会凭空长出来。

### 坐标基准参数化（已做，1.000 回归验证）

- 设计基准固定在八张 v4 原尺寸（`src/engine/art.js` 的 `REF` 表：七张 1086×1448，`f_eye` 单独 1254×1254）。`regions.json` 的数值、`REGISTER` 位移、`12_chorusx` 的 `HAND_CROP`、`lab.js` 的 `band`、场景里的 `/ 1086`，全部按设计单位理解——**换图后这些文件一个数都不用改**。
- `art` 对外收发设计单位，只有内部（mask、路径、位图、label 图）才用源像素；`sx = 源宽 / 基准宽`、`sy = 源高 / 基准高` 在装载时算一次。
- 回归证据：现有八张尺寸恰好等于基准（sx = sy = 1，换算全是恒等），改造后用同参数重渲染三张旧静帧，SHA256 与改造前**完全一致**（`out/reg_chorus.png`、`out/reg_shut.png`、`out/reg_alone.png`）。

### 因此，如果画师按 SVG 交付，规格加这几条（**已作废**，留档）

1. `viewBox` 的长宽比必须等于设计基准（七张 3:4、`f_eye` 1:1），构图/留白/配准与 v4 原图一致；改比例就是告诉引擎「整片每处裁切都拉扁」。
2. 根元素带 `width`/`height`，或至少让 `viewBox` 的单位够大（≥ 设计基准 2×，即 2172×2896 / 2508×2508）；否则解码尺寸就是 viewBox 单位，特写拿不到好处。
3. **只用填充路径**（`fill`），不要描边（`stroke`）、渐变、滤镜、位图、外链：管线是读像素分离三墨的，描边会把形体变成细线、渐变会把三墨分类打乱。
4. 三墨仍是 cream / orange / black（每通道 ±12），可以分三个图层、也可以做累进层（cream → orange → black）；透明底、主体外 alpha 0。
5. 交付即 `<矢量目录>/<name>.svg` 一套八张（原约定用 `assets/character_svg/`，该目录已于 2026-11-20 清出，真交付时新建即可），`node tools/art_dims.mjs --svg <矢量目录>` 应该看到 `sx == sy > 1.5`、无告警。

## 九、另一条试验线：用现成 Live2D 模型顶剪影（2026-11-17，结论：不做成品）

在等图期间，用《双生视界》高奈利亚的 Live2D 包跑过一轮：moc3 → 4096 透明渲染 → 三墨化 → 裁胸像 → 换进片子看 720p。**能跑通，但不能当成品**——自动三墨等于"自动上色"，帽子/蕾丝/棋格在 720p 下变成成片噪点块；重清理后又糊成一块；默认姿势头偏、裁切右边留白恒为 0（模型披风顶到画布边）。

对画师的意义只有一条：这套东西可以当**底稿**（在他描形之前先有一张占位的形），不要指望它替代设计。完整踩坑（Cubism 版本约束、参数名大写、`toDataURL`、`server.close()`、HSV 三墨规则、两档清理实测）记在 `踩坑与经验.md` 3.4。`assets/live2d/` 含第三方版权，不可随片发布。

**补充（同日，第二轮）**：`?box=x,y,w,h` 已修好——不裁不放大，直接按**模型坐标取材框**把 Live2D 渲成成品尺寸（`4344×5792` 2× 超采样 → 三墨化时一次降到 `2172×2896`），边缘比"全身图裁完再放大"干净（少了两次双线性，`out/_ref/edge_ab.png` 100% 对比）。但因此暴露一条**几何硬限制**：全身宽 923、胸像高 802（模型单位），3:4 框按高定时宽只剩 601～669，**披风必被切、左右留白做不到 5%**；要左右各 5% 就得把框放宽到 1000 左右，头会缩到画面 1/4 以下。原片 `f_bust` 自己也是满幅（bbox 1079/1086），所以这条不是裁切的锅，是形体比例。完整数据记在 `踩坑与经验.md` 3.5。

**补充（同日，第三轮·三点配准与特写验收）**：按 `regions.json` 的 `chin`/`flower`/`brooch` 三点反算取材框（`--box 355,100,918,1224`），`art_check` 位移从 133 px 降到 **10 px**，但**尺度差仍 25.3%**——这套模型没有横向铺开的长发，宽度填不满 3:4。**166.5 秒特写判不过**：原片靠"横向橙发 + 纯黑的脸"读成人形，这套三墨化后是竖条色块，脸的米白被镜头提亮打过曝；`--skin black` 与转正脸两种补救都无效。**结论：这套素材能当暗底背景色块，不能顶胸像特写。** 数据在 `踩坑与经验.md` 3.6。

**补充（同日，第四轮·换成做滤镜）**：八张图不是必须"画"或"描"出来的——把**三墨语言做成一层滤镜**（`tools/art_filter.mjs`：cover 定尺寸 → 双边平滑保边去纹理 → 语义分墨 → 众数清理 → 小连通块剔除 → PNG-24），任何输入（Live2D 渲染、截图、旧图、照片）都能收敛到本规格：三墨、alpha 255/0、3:4。实测 Live2D 全身图过一遍滤镜，`art_check` 位置对上（`cx` 0.497 vs 0.501），166.5 秒特写**读得出人**（此前 block 方案是竖条色块）。宽度差 25% 属形体比例，不是滤镜的锅。用法与参数见 `踩坑与经验.md` 3.7。

**交图要求不变**：仍按第 1–6 节，PNG-24、三墨 ±12、透明底、3:4、2× 设计基准。Live2D 这条线不改变清单；**若用现成素材过滤镜、三墨真的不够用**，才按下面第十节交七阶。

### 10.3 决定（2026-11-17）：先回原生图，滤镜与七阶暂缓

阁下拍板：**这一版继续用原生八张（`assets/character`），暂时不走滤镜那条路**。理由很干脆——滤镜出来的东西再"合规"，也不是这一版的画；它只证明了引擎能收七阶，不能替代画。

所以现在的口径：

- **片子跑原生八张**，`art_check` 实测 3–4 阶、构图零位移，与基线一致。
- **七阶引擎留着不拆**。它是已经验收过的能力，代码在 `src/engine/art.js` / `climax.js` 里，默认行为对三墨图**逐像素不变**；哪天有真画师交来七阶图，直接丢进素材目录就被认，不用再改代码。
- **滤镜只当工具保存**（`tools/art_filter.mjs`），不参与这一版出片。
- Live2D 那条线的成品（`assets/_test_art7` 等）留在本地候选，不入库、不上片。

一句话记：**滤镜证明的是"引擎能收"，不是"图能看"**。要更好看，还是得等真图。

## 十一、原生立绘：裁一刀直接用（2026-11-17）

新口径：**素材不二次加工**。原画本身什么样就什么样，只做"裁剪到剪影位"这一步，不过滤镜、不重上色、不做剪影分离。

**怎么告诉引擎**：素材目录里放一个 `raw.json`，列出"按图片印"的那几张：

```json
["f_bust", "f_profile", "f_reach", "f_eye"]
```

列在里面的键，`art.inks()` 直接 `drawImage` 印原图（保留透明通道、按 dst 缩放、支持 flip / reveal / alpha / crop），**不套 role 色、不做错版、不叠暗阶**；不在里面的键照旧走三墨/七阶剪影。两套可以混着放：露人的位置用图，其余位置保持剪影。

**裁剪**（`tools/art_crop.py` + `tools/art_crop_spec.json`）：

```
python tools/art_crop.py --src "<立绘.png>" --out out/_art/crop --spec tools/art_crop_spec.json
```

- `box` 是源图像素（也认 0..1 归一化），`size` 是剪影位尺寸（1086×1448，f_eye 1254×1254）。
- `"fit": true` 会先贴着 alpha 收掉白边、再按 size 的比例补透明边——原图的白边不该占剪影位。
- 只清一遍 `alpha<16` 的残点，别的一律不动。

**实测**（`assets/character_pic`，l2d16 西洋棋立绘 3060×4096，alpha 干净；该试验目录已于 2026-11-20 清出，本节为记录）：

| 位 | 取景 | 结果 |
| --- | --- | --- |
| f_bust | 头 + 半身 | 整张立绘读得满，透明底干净 |
| f_profile | 头 + 肩 | 同一张图换框，读作近景 |
| f_reach | 小臂 + 护腕 + 手 | 手是握着的，不是张开的（模型只有这姿势） |
| f_eye | 400×400 眼区 → 1254 | 眼睛、花饰都在，放大 3.1×，边缘仍锐 |

进片（163.5 / 166.5 / 170.19 / 20 秒）：不崩，构图位置与剪影版一致。

**代价**（照实说）：

1. 立绘是**冷色**（蓝发、白衣、红披风），片子整体是橙/米/黑的暖调——一进片就是"彩色照片贴在单色世界里"，视觉冲突是必然的。要收敛只有三条：换服装（找暖色那套）、调片子配色、或者接受这种冲突当风格。
2. 引擎为了兼容旧场景，**仍然会把这张图分一遍墨**（`art.inkAt` / `inkClip` / 部分特写与字格画面走掩膜）。所以"图片位"在别的地方可能露成剪影样，属已知瑕疵。
3. 这些图是第三方版权；试验产物一律落 `out/_art/`（已 ignore），**不入库、不可发布**。


## 十三、素材库：双生视界 Live2D（2026-11-17）

第 3.4 节那次试验只试了**一套**模型（`l2d16.u`），结论是"能跑通、不能当成品"。这一轮把

（15 角色 / 204 套 / 6,807 文件 / 1.84 GB），用法与配方写在 [`素材库.md`](../../二次创作/说明/素材库.md)。

**为什么值得接**：它不是图片库，是能摆姿势的模型——姿势、透视、发丝走向都有来源，
八张之间天然连贯；这正是"八次生图"和"手上现画"最缺的东西。

**这一轮实测**：

| 项 | 数 |
| --- | --- |
| 索引 | `docs/archive/v4/art/live2d_index.json`（204 套：三墨占比 / 贴图尺寸 / 动作数 / 表达式数） |

| 候选 | 四套正面像对照表 `out/_lib/candidates.png`（高奈利亚 l2d16 / l2d5017、菊理千姬 l2d28、朱诺 l2d5017） |

**能给的**：正/侧/低头/闭眼/伸手/捂胸；同一套衣服的连续取景；2048 贴图撑得住 2172 交付尺寸。
**给不了的**：无脸设计（模型有五官，`--skin black` 只压成黑块；自动补洞 `--faceless` 因头发压脸而失效，
只有 `--erase` 给框抹除才干净）、猫耳与猫爪、少年与成年男子；**侧脸也换不动**（`PARAM_ANGLE_X` 在这套模型上幅度极小，
要侧脸得走 motion 或换模型）；`f_eye` 的眼部特写拿不到 3000 长边的真细节（贴图 2048）。

或拿这套库当形体参考重描。

## 十五、真剪影模式（2026-11-17，B 方案）

A（占位稿）与 C（换语言）都绕不开「处理 ≠ 设计」（见 `踩坑与经验.md` 3.13）。B 是把内部信息全交出去：
**只留外轮廓，填一整块墨，边缘干净**——片子的美术本来就是这个语言，所以这条最不掉价。

```powershell
node tools/live2d_art.mjs ink --in out/_lib/p_face.png --out out/_lib/f_bust.png `
  --w 1086 --h 1448 --crop 1544,378,1266,1688 --silhouette --fill orange --stroke 0
```

- `--silhouette`：只认 alpha 外形，不做三墨分类。
- `--fill orange|cream|black`：整块填哪一墨。
- `--stroke n`：外缘黑边宽度（输出 px），0 = 不描。
- 内部在 **2× 超采样网格**上算，描完边再缩回输出尺寸，边缘是平滑墨线而不是硬台阶。
- 剪影模式下 `--erase` / `--island` / `--blue` / `--block` 都不生效（只认 alpha）。

### 描边：实测结论（原片根本没有外描边）

拿 `f_bust` 左缘做剖面（`y=300/500/700`，x 0–300）：颜色序列是 **透明 → 橙**，中间没有黑段；
黑色只出现在内部（脸的空块、裙摆）。所以：

1. **默认 `--stroke 0`**，与原片一致；边缘靠 2× 超采样给出干净的平涂切口。
2. 真要描边（有些镜头需要把剪影和暗背景分开），**1086 宽下不超过 6 px**。
   实测 10 px 描边会闭合内部缝隙（下巴与脖子之间、发丝之间），剪影从「人形」变成「一团」。
   黑边像素量：描边 6 → 2.6 万 px，描边 10 → 4.4 万 px（1086×1448 图内）。
3. 描边颜色用黑墨 `(36,26,21)`，不用纯黑，否则和片子的黑不同族。
4. 细发丝会被描边吞掉：宽度小于 2×描边宽度的细节直接消失，这是描边的物理代价，不是 bug。

### 「形」来自姿势与取框，不来自参数

四套模型剪影并排（`out/_lib/sil_shapes.png`）：

| 套装 | 剪影观感 | 问题 |
| --- | --- | --- |
| 高奈利亚 l2d16（棋塔装） | 帽子抢戏，像「棋帽少女」 | 道具盖住了头部轮廓 |
| 高奈利亚 l2d5017 | 手抬到下巴，剪影可读 | 肩膀被框切掉 |
| 菊理千姬 l2d28（白羽裙） | 双马尾 + 翅膀糊成一团 | 取框太松，翅膀与身体混在一起 |

结论：B 的八张必须**先定姿势（stand / idle，双手放下来）再定框**（头顶留 ~3%、肩膀完整、下缘切在胸下），
光调 `--crop` 和描边没用。
