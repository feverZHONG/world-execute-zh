# 剪影交付规格单

给画师照着做的一张单子。照这张单子交图，图放进 `assets/character/` 就能直接用，不用返工。
只要一页纸的版本（准备哪几张、多大、什么格式、交完怎么验）看 `交图清单.md`，这是它的详细依据。

本工程（`world-execute-中文版`）是《world.execute (me) ;》MV 的简体中文二创副本。片中的人物形象不是插画，是**三色剪影**：整张图只有橙、米白、近黑三种平涂，透明底，靠剪影轮廓和色块关系叙事。渲染器在载入时把每张图**一次性分墨**成三块版（米白 → 橙 → 近黑，按印刷顺序叠），之后全片只做裁切、上色、遮罩、网点、放大，不再读像素。所以图的规格不对，问题会直接进成片。

## 二、交付硬规格

每一条都会在 `tools/art_check.mjs` 里被量出来，规格不符会被标红。

1. **格式**：PNG-24，带 alpha 通道，无 ICC 配置（sRGB 即可）。不要 JPG、不要 WebP、不要带预乘 alpha。
2. **解析度**：胸像类长边 **≥ 2000 px**；会做特写的（`f_eye`、`f_reach`、单张的手）长边 **≥ 3000 px**。画布比例沿用现有分组：胸像类 **3:4 竖幅**（七张都是 1086×1448），脸部特写 **1:1**（`f_eye` 是 1254×1254）。同组图的比例必须一致，否则硬切会跳。
3. **透明底要干净**：主体内外都要干净——主体 **alpha=255**，主体以外 **alpha=0**；墨与墨、体与底之间的抗锯齿只允许 1–2 px 的过渡带，且过渡带内 alpha 也要落在 200 以上（不要画成半透明玻璃）。手动画的毛边、发光、投影一律不要。
4. **严格三墨**：只用上面三个色值，**每通道容差 ±12**。不要渐变、不要半透明色块、不要第四种颜色、不要高光点、不要描边线。原图 `f_reach` 里有一种偏锈的色（在橙与黑之间），现在靠分墨硬折叠进黑色，请不要再出现。
5. **不裁切、四边留白**：上、左、右三边各留 **≥ 长边的 5%** 空。**底边是例外**：胸像允许在一条水平线上切齐（现有八张都是切齐的），但请把切点放在文件底边一行内，不要留一半悬空。
6. **同组配准**：同一个人/同一组形象的图，下巴、花饰、领口必须落在**相同坐标**、大小一致。基准是 `f_bust`（1086×1448）：以它的下巴、发间花饰、领口三点为准，其余图照这三点对位。`cat_bust` 现在几乎能与 `f_bust` 重合，可以硬切；`boy_bust` / `man_bust` 现在需要缩放 0.89 / 0.873 才能对上，换图时**请直接画成能重合的尺寸**（渲染器里的 `REGISTER` 表就是为这三次校正存在的，能删掉最好）。
7. **分墨层（可选但很加分）**：如果能交三张同尺寸的分墨 PNG（`<name>_cream.png` / `_orange.png` / `_black.png`，各自只有该墨的 alpha）或一个分层的 PSD，载入时的自动分色就可以省掉，错版（套印不准）特效也会更干净。不给也不影响使用。

> 想改交 SVG（矢量）也可以，管线已经能吃，规格见第七节末「如果画师按 SVG 交付」五条：比例与配准不变、只许填充路径、三墨不变、尺寸按设计基准 2× 起。

## 五、交付流程

1. 照第二节做图，文件名按第三节（覆盖）或第四节的建议名（新增）。
2. 放进 `assets/character/`。
3. 跑 `node tools/art_check.mjs`：它会逐张量尺寸、留白、alpha、三墨，并和 `docs/v4/art/baseline.json` 比构图位移；加 `--strict` 时规格不符即返回非零。
4. 跑 `node export/export.mjs --sheet out/art_<name>.png --times <歌时间> --cols 1 --width 1280 --height 720`，看真实构图下的效果（这一步是肉眼验收）。
5. 同组配准若需要缩放/位移，把每张的「相对原图位移」读数一并给我，我来改 `src/engine/art.js` 的 `REGISTER`。

**注意**：`REGISTER` 里的位移是**源像素**（以 1086 宽的 `f_bust` 为基准），换更高的分辨率后要按「新图宽 / 1086」换算，这一条由接管方处理。

## 六、验收清单

脚本自动查：`node tools/art_dims.mjs`（源尺寸 / 设计基准 / `sx`、`sy` 是否相等 / 长宽比偏差 / 载入告警），`node tools/art_check.mjs`（文件是否存在、是否可解码、长边是否达标、四边留白、alpha 构成（残点 / 半透明 / 主体是否 255）、三墨偏差与「三墨以外的实体像素占比」、相对原图的构图位移与尺度差）。矢量交付时第二条要加 `--svg <目录>`。

肉眼查（每次换图必做）：把新图和原图在同一秒的静帧并排看——轮廓是否还认得出是她、橙块与米白块的分配是否还读得懂、缩小到 1280×720 时睫毛/发丝是否糊成一片、黑墨是否和页面底色糊在一起（黑墨几乎等于底色，每个用法都要有纸色、光或细线在后面托着）。

## 七、SVG 路线：实测结论（2026-11-16 第一轮）

**结论先写在前面：管线现在能吃 SVG、也能吃任意分辨率的大图（坐标基准已参数化并验证）；但把现有八张位图转成 SVG 没有可见收益——矢量化不增加信息。SVG 真正的价值在「画师按矢量交付」这件事上，不在「把 PNG 转一遍」。**

### 已打通的部分

- `loadArt` 支持可选 `cfg.paths.artSvg`（或启动参数 `?artsvg=`、导出参数 `--artsvg`）：按 `<目录>/<name>.svg` 取图，取不到就逐张回落 PNG 并 warn 一次。`src/engine/art.js`。
- `export/server.mjs` 的 MIME 表补了 `.svg`（原来没有 → 浏览器按 binary 拒解码，静默回落 PNG，这一坑实测踩过：两张 4K 静帧的 SHA256 完全相同）。
- `tools/raster_to_svg.mjs`：把三墨 PNG 矢量化成 `<name>.svg`，用的是引擎自己的分离和描线代码（`_prepareInk` + `trace.js` 的 `outline`/`smoothPath`），所以边界与片内一致；输出三块**累进版**（cream → orange → black，无孔洞、不依赖 fill-rule），单张 170–350 KB。
- SVG 只写 `viewBox` 时 Chrome 回落成 113×150 的固有尺寸，整张作废。现在 `loadArt` 会自动从 `viewBox` 补 `width`/`height`，同时检查两件事并 warn：长宽比偏离设计基准 >2%（片子里每处裁切都会被拉扁）、解码尺寸不足设计基准 1.5×（特写拿不到矢量的好处）。
- `tools/art_dims.mjs`（新增）：量一遍八张进管线时的真实源尺寸、设计基准、`sx`/`sy` 换算系数与长宽比偏差，并把上面的告警原样打出来。换图前后都该跑一遍。

### 实测数据（3840×2160 静帧，同一秒 PNG 版 vs SVG 版）

| 对比 | 结果 |
| --- | --- |
| `f_eye` 特写（166.5 秒），SVG 烘焙 **1254×1254**（与源同尺寸） | PSNR 37.4 dB；1:1 像素切片并排看不出差别 |
| `f_eye` 特写（166.5 秒），SVG 烘焙 **3000×3000**（放大 2.4×） | PSNR 42.5 dB，边缘略顺滑但**没有新增细节** |
| `f_reach` 手部特写（170.19 秒），SVG 烘焙 **2250×3000**，坐标基准参数化**之前** | 构图明显错位，PSNR **11.16 dB** |
| 同上，参数化**之后** | **38.5 dB**，并排看不出错位（`out/ab4k_png_s.png` vs `out/ab4k_svg_s.png`） |

第三、四行说明得很清楚：错位不是 SVG 的毛病，是源尺寸一变、场景里 1086×1448 的基准没跟着变。基准收进 `art` 内部之后，同一条边放大到 2.07× 仍然对得齐。

「位图矢量化不增加信息」这一条没变：同尺寸只是把同一条边重画一遍（37.4 dB），放大尺寸只是把同一条边画细（42.5 dB），细节不会凭空长出来。

### 坐标基准参数化（已做，1.000 回归验证）

- 设计基准固定在八张 v4 原尺寸（`src/engine/art.js` 的 `REF` 表：七张 1086×1448，`f_eye` 单独 1254×1254）。`regions.json` 的数值、`REGISTER` 位移、`12_chorusx` 的 `HAND_CROP`、`lab.js` 的 `band`、场景里的 `/ 1086`，全部按设计单位理解——**换图后这些文件一个数都不用改**。
- `art` 对外收发设计单位，只有内部（mask、路径、位图、label 图）才用源像素；`sx = 源宽 / 基准宽`、`sy = 源高 / 基准高` 在装载时算一次。
- 回归证据：现有八张尺寸恰好等于基准（sx = sy = 1，换算全是恒等），改造后用同参数重渲染三张旧静帧，SHA256 与改造前**完全一致**（`out/reg_chorus.png`、`out/reg_shut.png`、`out/reg_alone.png`）。

### 因此，如果画师按 SVG 交付，规格加这几条

1. `viewBox` 的长宽比必须等于设计基准（七张 3:4、`f_eye` 1:1），构图/留白/配准与 v4 原图一致；改比例就是告诉引擎「整片每处裁切都拉扁」。
2. 根元素带 `width`/`height`，或至少让 `viewBox` 的单位够大（≥ 设计基准 2×，即 2172×2896 / 2508×2508）；否则解码尺寸就是 viewBox 单位，特写拿不到好处。
3. **只用填充路径**（`fill`），不要描边（`stroke`）、渐变、滤镜、位图、外链：管线是读像素分离三墨的，描边会把形体变成细线、渐变会把三墨分类打乱。
4. 三墨仍是 cream / orange / black（每通道 ±12），可以分三个图层、也可以像 `raster_to_svg.mjs` 那样做累进层；透明底、主体外 alpha 0。
5. 交付即 `assets/character_svg/<name>.svg` 一套八张，`node tools/art_dims.mjs --svg assets/character_svg` 应该看到 `sx == sy > 1.5`、无告警。

### 所以下一步该做什么

1. ~~先参数化坐标基准~~ —— 已完成（见上）。
2. **SVG 的定位**：要么画师直接按矢量画（这时才真正兑现），要么画师按 ≥2× 设计基准交 PNG，`raster_to_svg.mjs` 转成 SVG 只当存档，不要指望画质。
3. 还有一个没做的可能性：让引擎**直接读 SVG 的路径**当绘制几何（现在是把 SVG 栅格化后重新描一遍，矢量的锐度被烘焙尺寸截断了）。这条路要等真有矢量源才有意义（拿自己描出来的 SVG 去验证是循环论证），方案已记在 `踩坑与经验.md` 的「仍未解决」里。
4. 现有八张的 SVG 副本（`assets/character_svg/`，约 1.9 MB）只作技术验证，素材本身仍是原片 CC BY-NC-SA，**不可随片发布**。

## 九、另一条试验线：用现成 Live2D 模型顶剪影（2026-11-17，结论：不做成品）

在等图期间，用《双生视界》高奈利亚的 Live2D 包跑过一轮：moc3 → 4096 透明渲染 → 三墨化 → 裁胸像 → 换进片子看 720p。**能跑通，但不能当成品**——自动三墨等于"自动上色"，帽子/蕾丝/棋格在 720p 下变成成片噪点块；重清理后又糊成一块；默认姿势头偏、裁切右边留白恒为 0（模型披风顶到画布边）。
