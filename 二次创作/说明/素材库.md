> 位置：`E:\DCIM\【OST】音乐、音效、视频\双生视界\【Live2D】（23.12.21）\live2d`
> 工程里的入口：`assets/live2d_lib`（**目录联结**，指向上面那个路径；`.gitignore` 里已忽略，不入库）
> 索引：`docs/archive/v4/art/live2d_index.json`（`python tools/live2d_index.py` 生成）

这是本机最完整的人形素材：**15 个角色 / 204 套模型 / 6,807 个文件 / 1.84 GB**，每套带
`.model3.json` + `.moc3` + 2048×2048 贴图 + 动作（部分套装 90 多条 motion）。
它不是"图片库"，是**能摆姿势、能换视角、能定格在任意动作上的活模型**——这正是剪影最缺的东西：
形体、透视、发丝走向都有来源，不用凭想象画。

---

## 一、为什么用它（和"生图/手绘"比）

| 路子 | 形体可信 | 可控性 | 代价 |
| --- | --- | --- | --- |
| 生图 | 看运气，八张之间不连贯 | 差（改一处全变） | 本工作区已禁 |
| 手绘 / SVG 路径 | 全靠手上功夫 | 高 | 慢，八张要画很久 |
| **Live2D 渲图 → 三墨** | **模型本身是原画师做的** | 中高：参数、动作、取框都能精确控制 | 细节会被三墨压平，且素材是第三方版权 |

结论：**形体与姿势靠它，风格与墨色靠 `ink` 压**。它不给"成品"，给的是"对的形"。

## 二、这条路能给 / 不能给

能给：

- 正面、侧面、低头、闭眼、伸手、捂胸…… 姿势与视角基本不缺（高奈利亚 1026 条 motion）
- 同一套衣服的连续八个取景，八张之间天然连贯（比"八次生图"强得多）
- 4K 级别的形体精度（贴图 2048，渲 4096 略放大，2172 长边交付绰绰有余）

不能给：

- **"无脸"设计**：模型有五官，`--skin black` 只是把脸压成黑块，五官仍在墨下面露边；`--faceless` 又因为
  头发与眉眼连通而判不出洞。**只能靠 `--erase` 给框抹除**（能抹干净，但框要人给、脸型也得人接受）。
- **侧脸**：这套 `l2d16.u` 的角度参数几乎不动，侧脸得靠 motion 或换模型。
- **猫耳 / 双拳当爪**：双生视界没有这套设定，`cat_bust` / `cat_paws` 仍要靠画（或拿别的模型硬改，效果未知）
- **少年 / 成年男子**：库里 15 个角色都是少女体型，`boy_bust` / `man_bust` 得另找源或手绘
- **发布合规**：这是游戏素材（第三方版权），**可以进片做试验，不能当"自己的美术"发布**。
  换掉原片 CC BY-NC-SA 剪影的初衷不变：真要发，这八张仍得由阁下/画师出，或用这套库当形体参考重描。

## 三、一句话总结

这是**形体库**，不是**成品库**：先在这里把"形"定准（姿势、透视、发丝），再决定它在画面里叫什么墨。
片子要的从来不是某一张画，是那套三墨语言；这套库能把"形"这一半做扎实，另一半（风格与无脸设计）还得人来定。

### 画板不再锁 1086：按源头原生像素重出（2026-11-18）

1086×1448 是这八张图最初的交付尺寸，但它是**设计基准**，不是分辨率上限——引擎按 `art.js` 的 `REF` 把任何尺寸映射回基准，所以画板本身可以更大而不动一处 crop。
`tools/plate_refit.py` 反解出每张的取框参数，`tools/plate_bake.py` 按「源头取框里真正有多少像素」重出（上限 2172 = 2× 基准）：

| 画板 | 现在尺寸 | 取框在源图里的原生宽 | 说明 |
|:--|:--|:--|:--|
| `cat_paws` | 1843×2457 | 1843（`plate_paws7.png` 3000 渲图） | 原来被缩到 1086，现在 1.7× |
| `cat_bust` | 1208×1611 | 1208（`plate_cat.png`） | 1.1× |
| `f_bust` | 1187×1583 | 1187（`hnl_bust.png` 4096） | 1.1× |
| `f_profile` | 1180×1573 | 1180（`plate_profile.png`） | 1.1× |
| `boy_bust` / `man_bust` / `f_reach` | 1086×1448 | 933 / 978 / 822 | **源渲图里人物只有这么宽**，画板本来就在 1.1–1.3× 放大；再大也是插值，没有新信息 |

回归验证：换成大画板后重出 100 s 那一帧，与旧成片同刻 **34.79 dB / SSIM 0.876**，与改之前的同口径数值一字不差——即 1080p 下画面无变化。
这条结论很重要：**1080p 不缺画板分辨率**（画板在片里基本是 1:1 或略缩），大画板买到的是**深裁切（如 170.19 那张 16:9 满版从 `f_reach` 底部取）与 4K 母版**的余量；真正的硬天花板是**渲图里人物占多少像素**，那是 Live2D 贴图 2048 决定的。

**`v2-proof` 的 4K 实测（2026-11-20）**：`plates_verse2.js` 的 `FIG` 是 840 设计单位，4K 下 1680 物理 px，对交付 `f_bust`（1841×2455）是 **0.91×**——这一镜并不放大；瓶颈仍是贴图 2048 里胸像约 1160 px，4K 下等于 1.45× 摊铺。从 4K 成片 1:1 裁 `out\_lib\p5\proof4k_mid.png`：发丝、蕾丝、chess 头饰高光边缘轻微软化，无锯齿，背景细网点无摩尔纹。结论：不缩尺寸、不加网点。

### 渲图尺寸才是真天花板：3000 → 5760（2026-11-18）

同一套衣服、同一姿势，只把渲图画布从 3000 换到 5760，裁成同样 1086 宽后比结构（梯度能量）：

| 渲图源 | 画板 1086 宽时的边缘能量 |
|:--|:--|
| 3000×3000 | 2.29 |
| 5760×5760 | 2.69（+17%） |

1:1 放大看，5760 那版的发丝与描边明显更利（`out/_lib/eye_a.png` ↔ `eye_b.png`）。原因是 3000 渲图里人物的取框只有约 933–1244 px，画板当年在做**放大插值**；5760 时取框有 1700–2400 px，画板终于能 1:1 落原像素。
所以**"被 live2d 出来的尺寸卡住"是真事**，解法不是把图拉大，是**换更大的画布重渲**（画布上限实测 5760；请求 6000 得 5760）。

**重出流程**（2026-11-18 起渲图自带参数留档，不再靠反解）：`node tools/live2d_art.mjs render --model "高奈利亚/<dir>" --out out/_lib/wr/big_XX.png --w 6000 --h 6000`
→ 渲完会在 PNG 旁边写同名 `.json`（模型、画布、pad/zoom、motion/t、包围盒、bboxW、顶端比例），
`python tools/plates.py cut --render <big> --name <画板名> --zoom 0.66 --top 0.02` 直接按相对包围盒裁，

- **验收口径就用成片帧**：`tools/plate_pick.py`（本轮新建）裁一版 → 出同刻帧 → 跟改前帧比 PSNR，取最高。`f_reach` 在 170.20 上扫出来的最优是 `zoom .470 / top 0 / cx .473`（30.48 dB），离这点 ±2% 的 zoom 或 ±0.002 的 cx 立刻掉到 17–24 dB——**取框对位是窄谷，不能用平均差找，只能用画面找**。
- `f_profile`（114.90 帧）和 `cat_paws`（180.60 帧）对 ±2% 的取框变化不敏感（26.2–26.3 / 21.92 恒定），说明它们在这两个 shot 里的像素占比小、或走剪影通道；这两张按目视并排（`out/_lib/try_prof_pair.png`、`try_paws_pair.png`）定的框。

### 四张胸像的纵向取景差（2026-11-18 量过，没动）

`f_bust / boy_bust / cat_bust / man_bust` 用的是同一个模型、同一个默认姿势，但**取景高低差得很远**：
`f_bust` 顶着棋盘高帽，帽顶占了画面上端，所以她的下巴落在 y≈1126（design px，78% 高度）；
三张"换装胸像"没有帽子，下巴在 678～727（约 48–50%）。也就是说同在 `FIG` 里按同一 size 画，
她的脸比他们低两三百像素——`plates_pre2.js` 的 gender 那一下本来就要跳。

用 `tools/plate_delta.py`（旧画板 ↔ 新画板 alpha 互搜）核对：`boy_bust`、`cat_bust` 的平移是 **(0, 0)**
（换成 5760 重出时取景没漂），`man_bust` 是 (−10, +10)。所以**换画板没有引进新的跳动**，现在看到的差是原本就有的。
