# 素材库 · 双生视界 Live2D（形体来源）

> 位置：`E:\DCIM\【OST】音乐、音效、视频\双生视界\【Live2D】（23.12.21）\live2d`
> 工程里的入口：`assets/live2d_lib`（**目录联结**，指向上面那个路径；`.gitignore` 里已忽略，不入库）
> 索引：`docs/v4/art/live2d_index.json`（`python tools/live2d_index.py` 生成）

这是本机最完整的人形素材：**15 个角色 / 204 套模型 / 6,807 个文件 / 1.84 GB**，每套带
`.model3.json` + `.moc3` + 2048×2048 贴图 + 动作（部分套装 90 多条 motion）。
它不是"图片库"，是**能摆姿势、能换视角、能定格在任意动作上的活模型**——这正是剪影最缺的东西：
形体、透视、发丝走向都有来源，不用凭想象画。

## 一、为什么用它（和"生图/手绘"比）

| 路子 | 形体可信 | 可控性 | 代价 |
| --- | --- | --- | --- |
| 生图 | 看运气，八张之间不连贯 | 差（改一处全变） | 本工作区已禁 |
| 手绘 / SVG 路径 | 全靠手上功夫 | 高 | 慢，八张要画很久 |
| **Live2D 渲图 → 三墨** | **模型本身是原画师做的** | 中高：参数、动作、取框都能精确控制 | 细节会被三墨压平，且素材是第三方版权 |

结论：**形体与姿势靠它，风格与墨色靠 `ink` 压**。它不给"成品"，给的是"对的形"。

## 三、索引（选型不再靠翻目录）

```powershell
python tools/live2d_index.py            # 扫全库，产 docs/v4/art/live2d_index.json
python tools/live2d_index.py --top 20   # 顺带列橙+米白占比最高的 20 套
```

索引里每套模型记这几件事：角色 / 模型目录 / model3 名 / moc3 体积 / 贴图数量与最大尺寸 /
**三墨占比（cream / orange / black）** / 动作数 / 表达式数。三墨占比用与 `ink` 同一套 HSV 规则算，
所以能直接预判"这套渲出来大概是什么形状"：

- `orange` 高：有大量暖色/彩色布料（橙墨会占主体）
- `cream` 高：白衣、浅色系（适合压"米白为主体"的画面）
- `black` 低（多数套装 <1%）：说明贴图本身很亮，黑墨主要来自 `--keyline` 的黑边，而不是素材

角色平均（橙+米白占比）：菊理千姬 98.9 / 阿尼娅 98.9 / 洛可可 98.3 / 唯 97.4 / 艾琳 97.3 …
高奈利亚 24 套、1026 条动作，是动作最全的一个。

## 四、渲染与压墨（配方）

```powershell
# 1) 渲透明 PNG（角色/目录，任意姿势）
node tools/live2d_art.mjs render --model "高奈利亚/l2d16.u" --out out/_lib/bust.png --w 2048 --h 2048 `
     --pad 0.96 --params "PARAM_ANGLE_X:0,PARAM_ANGLE_Z:0"

# 2) 压成三墨并按交付尺寸出图（--crop 是源像素 x,y,w,h）
node tools/live2d_art.mjs ink --in out/_lib/bust.png --out out/_lib/f_bust_ink.png `
     --w 2172 --h 2896 --crop 1560,380,1200,1600 --skin cream --block 5 --clean 3 --keyline 4
```

参数怎么调（实测）：

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| `--pad 0.94`（默认）/ `0.96` | 角色占画布比例 | 全身 0.94；只取上半身反而要 `--box` 更准 |
| `--params` | 叠参数改姿势 | `PARAM_ANGLE_X:0,PARAM_ANGLE_Z:0` 是正面；`-62` 近似侧脸；`PARAM_EYE_L_OPEN:0` 闭眼 |
| `--motion` + `--t` | 定格某条动作 | 伸手、捂胸这类姿势靠它，比自己拧参数快 |
| `--box x,y,w,h` | 模型坐标取框，直接渲成成品尺寸 | 胸像/特写用它，比事后裁切准 |
| `--block n` | 降采样"只取形体" | 3 = 保留五官，5 = 更平更像剪影（实测 5 更干净） |
| `--clean n` | 3×3 众数清理 | 3 能把发丝间碎点吃掉大半 |
| `--keyline n` | 输出黑边宽度 | 3–6；0 关掉会散 |
| `--skin cream\|black` | 皮肤走哪一墨 | `cream` = 有脸；`black` = 靠近原片"无脸"设计 |
| `--erase x,y,w,h` | 手工抹除（输出像素，多块用 `;`） | **无脸化的实际出口**：框住眉/眼填成皮肤墨，见下节 |
| `--blue s` | 蓝→橙 的饱和度阈值（默认 0.12） | 发面高光会漏成米白白洞；`0.005` 基本吃干净 |
| `--island n` | 小于 n 像素的色块并回周围主墨，并回填内部透明小洞 | **治碎斑的关键**：12000 起（1086×1448 档），蕾丝/花纹/发高光都被吃掉 |

### 无脸怎么来（这条是卡点）

片子无脸，模型有脸。四条路里只有最后一条可靠：

| 试法 | 结果 |
| --- | --- |
| `--skin black` | 五官仍在墨下面露边 |
| `--block 8/12` | 脸压平大半，眉和眼还留两块 |
| `--faceless` | **失效**：头发压脸，眉眼与头发连通，泛洪判不出"洞" |
| `--erase` | **有效**：人给框，工具抹净 |

```powershell
node tools/live2d_art.mjs ink --in out/_lib/p_front.png --out out/_lib/i_front_face.png `
  --w 724 --h 966 --crop 772,189,633,844 --block 6 --clean 3 --keyline 4 --erase "420,505,152,122"
```

`--erase` 在 keyline 之前跑，抹掉的区域不会再勾出内线。无脸是设计决定，框得人给。

再走一遍收图流水线，把它归位到片子基准：

```powershell
python tools/art_intake.py --src "<把压好的图按 <key>.png 命名的目录>" --preview 20,166.5
```

## 五、已经跑通的证据（2026-11-17）

| 步骤 | 结果 |
| --- | --- |
| 高奈利亚 `l2d16.u` 渲 4096 透明图 | 一次成功，`canvas 1500x1500 @256.7%` |
| 同图压三墨（`--block 3` / `5`） | 覆盖 56.2%，cream 35.2 / orange 47.6 / black 17.2；蓝发→橙墨、白布→米白、深色→黑 |
| 四套候选正面（`out/_lib/candidates.png`） | 高奈利亚 l2d16（棋塔装）/ l2d5017 / 菊理千姬 l2d28（白羽天使裙）/ 朱诺 l2d5017 |
| 五取景（正面 / 侧脸 / 闭眼 / 手到胸前 / 眼部特写） | `out/_lib/five_views.png`；四条能出，**侧脸换不动**（见下） |
| 无脸化（`--erase`） | 724×966 胸像抹净五官，`out/_lib/i_front_face.png` |

实测出来的两个硬边界：

- **侧脸换不动**：`PARAM_ANGLE_X` 从默认 −30 调到 0、再调到 −62，同一套模型渲出来的 bbox 几乎不变
  （`623,207,1553,2047` vs `623,202,1553,2047`）——角度参数在这个模型上幅度极小。
  要侧脸得走 motion（`l2d5017.u` 有 `Mgirl02_celian`），或换一套角度变形明显的模型。
- **眼部特写分辨率不够**：贴图 2048，脸在贴图里只占一小块，4096 渲图裁出来再放大到 3000 长边是虚的。
  `f_eye` 那张要么接受放大、要么另画。

对照表看得很清楚：这套库的"原画质量"足够撑特写，**短板不在形体，在"三墨化之后还剩多少"**——
`--block` 越小越像插画、越大越像剪影，中间那一档要按镜头定。

## 六、这条路能给 / 不能给

能给：

- 正面、侧面、低头、闭眼、伸手、捂胸…… 姿势与视角基本不缺（高奈利亚 1026 条 motion）
- 同一套衣服的连续八个取景，八张之间天然连贯（比"八次生图"强得多）
- 4K 级别的形体精度（贴图 2048，渲 4096 略放大，2172 长边交付绰绰有余）

不能给：

- **"无脸"设计**：模型有五官，`--skin black` 只是把脸压成黑块，五官仍在墨下面露边；`--faceless` 又因为
  头发与眉眼连通而判不出洞。**只能靠 `--erase` 给框抹除**（能抹干净，但框要人给、脸型也得人接受）。
- **侧脸**：这套 `l2d16.u` 的角度参数几乎不动，侧脸得靠 motion 或换模型。
- **猫耳 / 双拳当爪**：双生视界没有这套设定，`cat_bust` / `cat_paws` 仍要靠画（或拿别的模型硬改，效果未知）
- **少年 / 成年男子**：库里 15 个角色都是少女体型，`boy_bust` / `man_bust` 得另找源或手绘
- **发布合规**：这是游戏素材（第三方版权），**可以进片做试验，不能当"自己的美术"发布**。
  换掉原片 CC BY-NC-SA 剪影的初衷不变：真要发，这八张仍得由阁下/画师出，或用这套库当形体参考重描。

## 七、一句话总结

这是**形体库**，不是**成品库**：先在这里把"形"定准（姿势、透视、发丝），再决定它在画面里叫什么墨。
片子要的从来不是某一张画，是那套三墨语言；这套库能把"形"这一半做扎实，另一半（风格与无脸设计）还得人来定。

## 十一、八张画板全是她（2026-11-17 定稿）

片里原来有八张画板（她、她的侧脸、她伸手、她的眼、少年、男人、猫耳的她、扑爪）。
现在**八张全部来自高奈利亚本人**，只是各换一套模型与姿势。`assets/character/` 里就是这些图，
`assets/character/raw.json` 把八个名字都列进「原图直印」，引擎不再压墨、不染色。

| 画板 | 来源模型 | 怎么来的 |
| --- | --- | --- |
| `f_bust` | 高奈利亚 `l2d16.u`（西洋棋） | 4096 渲图，胸像取框 |
| `f_eye` | 同上，脸特写 | 4096 图里裁 1254×1254 |
| `f_reach` | 同上，伸手定格 | 4096 渲图 |
| `f_profile` | `l2d5017.u` + `Mgirl02_celian`（t=0.3） | 库里**唯一真有侧脸**的动作：头转过去、闭眼、手按胸前 |
| `boy_bust` | `l2d01.u`（橙白棒球外套） | 短发＋少年体态，色调与原片的橙最接近 |
| `man_bust` | `l2d19.u`（战术头盔＋面罩） | 头盔压住眉眼＝天然无脸，体量对得上「成年」 |
| `cat_bust` | `l2d06.u`（猫耳连帽衫） | 两只青蓝猫耳＋耳机＋围巾，同一画面里 |
| `cat_paws` | `l2d06.u` + `Mgirl02_dazhaohu`（t=0.9） | 一条手臂横伸出去＝扑爪；手套原本就是厚爪形 |

**取框工具**：`tools/plate_cut.py`，把渲图按包围盒裁成 1086×1448 竖幅。
`--zoom` 的含义是「裁切宽 = 包围盒宽 × zoom」，所以**数值越小越贴近**
（0.45 ≈ 脸的特写，0.6 ≈ 头肩，0.9 ≈ 半身）。

```powershell
python tools/plate_cut.py --in out\_lib\plate_cat.png --out out\_lib\try_cat.png --zoom 0.75 --top 0.0
```

**为什么没跨角色反串**：库内 16 位全是少女，没有男性、也没有猫。拿别人去顶「少年／男人／猫」，
原片那种「同一朵花、同一件领子」的一家人设定会立刻散掉；换成她本人的另一套装束，血缘至少是通的。

**配准（REGISTER）**：三张与之对位的画板重算过——`cat_bust [1.0,-40,-2]`、`boy_bust [1.0,-10,0]`、
`man_bust [1.0,0,-3]`。三张都是满幅胸像，包围盒贴着画布边，所以尺度只能是 1.00；
**按五官对脸的精配还没做**，`art_check` 也会报「位移过大」——先认这条账。

**代价（记在案）**：原片是刻意无脸的三墨剪影，现在是全彩原图、五官清楚，片子「无脸」的设定到此结束。

### 用法（三步）

```powershell

```

**踩过的坑**：`l2d07` 这件是紧身战术连身，`--zoom` 要比 06 小一点才不会把尾巴切掉；
`l2d80011.u` 只有纸伞部件，渲出来是一把伞，不可当人物用；`l2d00.u` 是素体，别误用。
