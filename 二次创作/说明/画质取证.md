# 画质取证：成片到底丢了多少

## 一、口径

拿**页面渲染的原始像素**当参考：`--frame png --frames <dir>` 让导出把每帧 PNG 原样落盘（不经过任何编码），
再从成片里抽同一时段的连续帧，逐对算 PSNR / SSIM，取最接近的一对——因为切片与成片相差几帧，不先对齐，
量出来的只是运动位移，不是编码损失。

```powershell
# 1) 参考：t 附近 0.5 s 的原始像素
node export/export.mjs --frame png --start 45.0 --end 45.5 --width 1920 --height 1080 --fps 60 `
  --frames out\_lib\dump454b --out out\_lib\lp3.mp4
# 2) 成片同段连续帧
ffmpeg -y -ss 49.9 -i out\preview_1080p60.mp4 -frames:v 36 out\_lib\filmseq\g%02d.png
# 3) 对齐 + 出数
python tools\compare_frames.py 45.4          # 读 ref_/film_ 前缀；对齐版见下
```

## 二、实测（1920×1080 / 60 fps / 25 Mbps，0.2 bpp）

| 时刻 | PSNR | SSIM | 平均 \|Δ\| | p99 \|Δ\| | 暗部色阶 | 色偏（R/G/B） |
|:--|:--|:--|:--|:--|:--|:--|
| 45.4 s | 37.5 dB | 0.919 | 2.46 / 255 | 9 | 33（参考 31） | 未见明显漂移 |
| 180.0 s | 35.7 dB | 0.927 | 2.76 / 255 | 16 | 36 | −1.0 / −1.2 / −0.8 |

判据来自画面本身，不是分数本身：

- **暗部平滑度**：暗区相邻像素平均步长 1.26（参考 2.67）。编码把画布抖点抹平了，方向是对的；不是色带。
- **色阶**：暗部仍保留 33–36 个独立亮度级，没有坍塌（色带的表现是级数骤降）。
- **文字边缘**：1:1 放大对照（`out\_lib\cropdiff.png`）里中英文笔画的抗锯齿与描边都在，没有糊边、没有振铃。
- **色偏**：全程在 ±2 以内，是 limited range 取整的正常量。

结论：**0.2 bpp 对这套扁平美术（大面积纯色 + 细线 + 文字）冗余足够**，肉眼与源画布无差。
要更保险可 `--bpp 0.3`（≈37 Mbps，整片体积约 1 GB，耗时不变）。

## 三、取证路上踩到的两个坑（都别再踩）

1. **`--frame raw` 通道现在是有病的**：同样时段，raw 落盘的画面是逐行彩虹条纹（每行一个纯色），
   而 jpeg / png / h264 三条通道同一时刻都正常。raw 已不作为任何取证基准；日常导出也不走它。
2. **mosh 段落不能用短切片或 contact sheet 当参考**：那种效果依赖上一帧状态，起手几帧处在异常态，
   满屏彩虹。任何单帧取证都必须让渲染**连续跑过那段**（≥1 s 预热），或者干脆从成片抽帧。

## 四、什么时候该重跑这张表

改了美术、改了主色、改了编码参数（`--bpp`、GOP、`preset`）之后。只改文案不用重跑。
