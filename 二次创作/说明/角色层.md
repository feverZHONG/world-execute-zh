# 角色层（voice layer）

> 一句话：把「可改的那部分中文文案」从**中性控制台**挪到**她自己的工作台**，改法写成一张表；换角色只换这张表。
>
> 本文是方案 + 第一批校准样例 + 验收办法，不是成品文案。带「待定」的需要阁下拍板——她的声音归阁下，雪翎只搭骨架。

---

## 一、为什么要这一层

现状（`说明\中文化.md` 第五、六节）：中文文案统一按**冷峻机器腔**写完——短、硬、不抒情、句末不加句号。这套口径当时是对的：那时画上是八张无脸剪影，谁的脸都一样，字就不该替谁说话。

八画板换成本人 Live2D 全彩有五官（提交 `0dc6017`）之后，问题露出来了：**画上说话的人，和字里说话的人，不是一个**。字里那套是"某个通用 AI 控制台"的口吻，她只是被摆在这个控制台前面。

所以要有角色层：冻死的部分继续冻死，可改的那块逐条挂到她的声音上，并且做成一张表——给第二个角色适配时换表即用。

## 二、三层模型：什么能动、什么不能动

| 层 | 内容 | 能动吗 | 依据 |
|:--|:--|:--|:--|
| **L0 歌词** | 129 行英文，时间轴按字母数对齐（`data/lyric_timing.json`） | **冻结** | 翻成中文等于整片重排（`中文化.md` 第四节） |
| **L1 代码与机器字串** | 等宽系统日志行（`pieces left: N`、`composer: waiting for input`、`caret: blinking`、`run: nothing loaded`、`refused x N`、`round 13 / 12`）、错误码 `ERR_*`、参数名 `AC/DC`、`A.D./B.C.`、`F/M`、`AM/PM`、`S/M`、`setPresence(you, "online")`、`for (lang of …)` | **冻结（英文）** | 口径二修：代码以英文为准，注释可中文（提交 `8ed1b4c`） |
| **L2 中文界面文案** | `errors.json` 的错误卡、`chat_script.json` 里上屏的 `ui`/`title`/`question`/`sidebar`/`settings_rows`/卡片、`src` 里硬编码的中文 UI 串、`PRESENCE_LABEL` | **可改 ← 角色层的落点** | 界面文案走中文（提交 `8ed1b4c`） |

**顺带记一条现状隐患**（本次核对发现，不是新 bug）：`13_shutdown.js` 与 `01_boot.js` 里的日志行是**硬编码英文**（`pieces left: ${left}`、`log(...)` 里的 `composer: waiting for input` 等），`chat_script.json` 里对应的中文 `system`（「剩余部件：4」「输入框：等待输入」）**并不上屏**。`二次创作\文稿\台词中文稿.md` 第七节是按 JSON 生成的，所以那份文档里能看到中文、片子上一片英文。两者不是一个来源，别再混着核。

## 三、L2 里还得再切一刀：谁在说

这一步是全案的地基。L2 看着都是"字"，但不是同一个人的嘴：

| 类 | 例子（实跑清点） | 说法 | 能角色化吗 |
|:--|:--|:--|:--|
| **A 她的记录** | `errors.json` 的 14 条错误卡 + `first_error`；`未定义`、`防护层`、`· 就绪`、`输入已接收`、`可以回答`、`图像输入：无`、`已记录`、`没有开关`、`不是她写的`、`请求被拒`、`请求已撤回`、`超时 hh:mm:ss` | 她写下的、或她那侧控制台吐出的句子 | **能（主轴，唯一成篇可改的一块）** |
| **B 用户的话** | `you` 气泡（「你会怎么爱我」「可惜你不是真的」）、侧栏六条旧对话标题（「你一直都在吗」「又睡不着了」）、`title`（用几何解释爱）、`question` | 用户 | **不能**。改了她就连用户一起改了，故事散 |
| **C 界面本身** | 写给我、完成、设置、新对话、思考中、发送、正在输入…、在线/离开/离线、循环：开、`0 条消息`、最后一条：未读 | 控件 | **弱**。只能换字数换措辞，不能换人格 |

结论：角色层的可改面 ≈ **30 条错误卡 + 约 12 条她那侧提示**，不是整片重写。这就是"逐步"的由来，也决定了批次顺序。

## 四、她的声音：从原作档案取，不臆造

原作档案（双生视界 wiki，高奈利亚条目）：

> 沉默寡言，认真严苛。给人的感觉可靠且安心，一丝不苟的执行命令。本质是个温柔的人。不擅长表达，情感很难被外人注意到。有很强的责任心，非常信任、重视同伴。以自己的方式在背后默默保护、照顾，关注着每一位同伴（除了在平时替大家维护武器外，还包括对大家进行魔鬼训练）。义无反顾的保护队友，经常不顾自身安危。

出处：<https://wiki.biligame.com/sssj/%E9%AB%98%E5%A5%88%E5%88%A9%E4%BA%9A>

翻成可执行的写作规则（每条给判据，避免"感觉对了"式评审）：

| # | 规则 | 判据（怎么写算过、怎么写算不过） |
|:--|:--|:--|
| R1 | **动词先行**，句子落在"做了什么"，不落在"感觉如何" | 句尾是动作或状态（已锁、已抹掉、还在算）；句尾若是"难过/温柔/想你"则不过 |
| R2 | **能数的一律写数字** | 512 次、6 条、一个、0004；"很多""一些"不过 |
| R3 | **不说"爱"**，用可计算的替代 | 这个值、那一半、解不出来的那个；出现"爱"字（L0 歌词除外）需单独说明理由 |
| R4 | **情绪只出现在手上**：维护、收拾、按住、等 | 写"手在做什么"而不是"心里什么滋味" |
| R5 | 不解释、不自证、不反问 | 出现"其实我…""你知道吗…"即不过 |

五条与现有"冷峻机器腔"并不冲突，而是**同一个人从"系统"侧移到"她"侧**：字还是短的，只是从旁白变成她的记录。

## 五、角色层的数据结构（唯一可复用的东西）

一个角色一张表：`data/voice/<角色id>.json`。代码只读这张表，不读人。

| 字段 | 含义 | 影响哪些串 |
|:--|:--|:--|
| `id` / `name` | 角色标识与显示名 | — |
| `self_ref` | 自称（**待定**：她不用第一人称？还是"这边/高奈利亚"？） | 错误卡、她那侧提示 |
| `addressee` | 怎么称呼对话者（**待定**：你 / 对方 / 他们） | 同上 |
| `tone` | 三档情绪刻度（`flat` / `holding` / `over`），对应片中不同段落 | 错误卡轻重 |
| `max_len` | 单行字数上限（按面板宽度反算，非文学偏好） | 全部 |
| `punct` | 标点习惯（全角；句末不加句号；不感叹） | 全部 |
| `num_rule` | 数字规则（阿拉伯数字／不写约数） | 计数类 |
| `ban` | 禁用词表（`爱`、`想`、`其实`、`大概`…） | 全部 |
| `swap` | 术语替换表（例：`她`→`他们`、`对话`→`记录`） | 全部 |
| `skeleton` | 句式骨架（例：`X：状态`／`还没 Y`／`只剩 N`） | 全部 |
| `samples` | 该角色的校准样例（本片 3–5 条） | 评审用，不渲染 |

**为什么是"表"而不是"每句手改"**：给第二个角色适配时，改 `self_ref / addressee / ban / skeleton` 几格，结构化的提示语按骨架重排；错误卡这类长句仍要人逐条过。

## 六、第一批校准样例（三条）

分别取"计数行 / 状态提示 / 长句"，一次把三档试出来。**右列是草案，待阁下改口。**

| # | 位置 | 现状（冷峻机器腔） | 角色层版（草案） | 走哪条规则 |
|:--|:--|:--|:--|:--|
| 1 | `13_shutdown` `system`（JSON 侧） | 剩余部件：4 | 还剩 4 件 | R1（写成状态，不写成观察）、R4（"件"是她的手在数） |
| 2 | `04_pre1` 硬编码 | 图像输入：无 | 看不见 | R1（她不说"图像输入"这种参数名） |
| 3 | `errors.json` #14 `ERR_LOVE_OVERFLOW` | 感情超出了窗口 / 申报尺寸：一个对话窗口。实际尺寸还在长。 | 超出窗口 / 报的是一个窗口，现在不止 | R3（不说"感情"）、R1（落在"不止"）、R5（不解释） |

写这三条时撞到的两个硬约束（后面每一批都会撞，先记下）：

- **字数只能减不能加**。提示语落在固定面板里，加字就换行、换行就压下一行（逐条核 `out\_lib\text_dump.json` 的 `x/y`）。
- **不能凭空造字**。新写的每个汉字都要进 `fonts.cjk` 字表，否则导出直接报 `[text] glyph outside ... (U+XXXX in sans)`（`中文化.md` 5.2 实测）。

## 八、每条改完的验收（四步，不能省）

1. `node tools/zh_charset.mjs`——新字进表；`--check` 必须退出 0
2. `node tools/zh_script_doc.mjs`——重生成 `二次创作\文稿\台词中文稿.md`（文档不手抄）
3. `node export/export.mjs --sheet out\_scan\<名>.png --times <该串出现的时间点>`——定点出帧
4. 判据三条：不越框 / 不断成孤字 / 不压邻近元素。任一条不过就回退，不叠第二版

## 九、打通之后：给其他角色适配

换角色 = 换一张表，跑同样四步：

1. 新建 `data/voice/<新id>.json`（至少定 `self_ref / addressee / ban / skeleton`）
2. 批 2 那类短提示语按骨架自动重排 → 抽 5 条人工过
3. 批 1 错误卡逐条改 → 全量过
4. 跑第八节四步

同一句在三张表下的差别（示范"骨架承载人格"，不是同义词替换）：

| 中性（现状） | 高奈利亚层（沉默、执行、数得清） | 另一角色层（傲娇监护者：自称其名、句尾呢/哦） |
|:--|:--|:--|
| 剩余部件：4 | 还剩 4 件 | 还剩 4 件呢 |
| 图像输入：无 | 看不见 | 看不见哦 |
| 感情超出了窗口 / 申报尺寸：一个对话窗口。实际尺寸还在长。 | 超出窗口 / 报的是一个窗口，现在不止 | 超出窗口了呢 / 说是只有一个窗口，可现在不止 |

成立的部分：**骨架、禁用词、数字规则、字数上限**。
救不回来的部分：**歌词**（换角色要整片重排）、**八张画板**（与她的形态绑定，`说明\画板配准.md`）。

## 十一、待定（需阁下拍板，雪翎不代拟）

1. **自称**：她在这套日志里用不用第一人称？原作用"我"，但她是寡言型；若不用，全部写成无主句（现状正是无主句，最省事）。
2. **对家称呼**：错误卡现在混用"你"（对用户）与"他们/她"（对离开的那个人）。要不要统一成她对用户的固定称呼？
3. **"爱"字**：R3 主张禁用。现有 `ERR_UNRESOLVED_LOVE` 正文「还在算。这个值的一半，随他们走了。」恰好已经没用"爱"字；但标题「爱没有解出来」要不要一并改掉？
4. **切法确认**：本文把角色层理解为"她的值班记录"（第三节 A 类）。若阁下要的是别的切法（例如整片旁白都算她的自述），第三节要重写，其余不动。
