# 角色层（voice layer）· 通用规范

> 本文只管**机制**：分层、归属切分、角色卡与数据表的约定、批次流程、验收办法、模板。
> **具体角色的声音不写在这里**——一个角色一张角色卡，见 `说明\角色\` 下对应文件（本片指定角色：`说明\角色\高奈利亚.md`）。
>
> 目的是"换个角色只换一套文件，不动代码、不动片子结构"。

---

## 一、为什么要这一层

中文文案曾统一按**冷峻机器腔**写完（`说明\中文化.md` 第五、六节）：短、硬、不抒情、句末不加句号。那套口径成立的前提是画上八张无脸剪影——谁的脸都一样，字就不该替谁说话。

八画板换成某个具体角色的全彩有五官之后（本片：提交 `0dc6017`），前提不再成立：**画上说话的人，和字里说话的人，不是一个**。字里那套是"某个通用 AI 控制台"的口吻，角色只是被摆在这个控制台前面。

角色层做的就是这件事：冻死的继续冻死，可改的那块按**指定角色**重写，并且做成一张表，让下一个角色复用。

## 二、三层模型：什么能动、什么不能动

| 层 | 内容 | 能动吗 | 依据 |
|:--|:--|:--|:--|
| **L0 歌词** | `data/lyric_timing.json` 的 129 行（英文，时间轴按字母数对齐） | **冻结** | 翻成中文等于整片重排（`中文化.md` 第四节） |
| **L1 代码与机器字串** | 等宽日志行（`pieces left: N`、`composer: waiting for input`、`caret: blinking`、`run: nothing loaded`、`refused x N`、`round 13 / 12`）、错误码 `ERR_*`、参数名 `AC/DC`、`A.D./B.C.`、`F/M`、`AM/PM`、`S/M`、`setPresence(you, "online")`、`for (lang of …)` | **冻结（英文）** | 口径二修：代码英文、注释可中文（提交 `8ed1b4c`）。**细则与"不是漏翻"清单见 `说明\语言边界.md`**（2026-11-18 拆出） |
| **L2 中文界面文案** | `errors.json` 错误卡、`chat_script.json` 中上屏的 `ui`/`title`/`question`/`sidebar`/`settings_rows`/卡片、`src` 里硬编码的中文 UI 串、`PRESENCE_LABEL` | **可改 ← 角色层的落点** | 界面文案走中文（提交 `8ed1b4c`） |

**现状隐患（本规范落稿时核对发现，非新 bug）**：`13_shutdown.js` / `01_boot.js` 的日志行是**硬编码英文**（`pieces left: ${left}`、`composer: waiting for input` 等），`chat_script.json` 里对应的中文 `system`（「剩余部件：4」「输入框：等待输入」）**并不上屏**。`二次创作\文稿\台词中文稿.md` 第七节按 JSON 生成，所以那份文档能看到中文、片子上是英文。两者不是一个来源，核对时别混。

## 三、L2 里还得再切一刀：谁在说

这是全案地基。L2 看着都是"字"，但不是同一个人的嘴。**三个人（或三样东西）**，各自的嘴不能串：

| 类 | 说话人 | 内容 | 说法 | 落点文件 |
|:--|:--|:--|:--|:--|
| **A 她的记录** | **高奈利亚** | `errors.json` 的 `spread` 14 条 + `first_error` 的标题与正文；她那一侧的提示语（`未定义`、`防护层`、`· 就绪`、`输入已接收`、`可以回答`、`图像输入：无`、`已记录`、`没有开关`、`不是她写的`、`请求被拒`、`请求已撤回`、`超时 hh:mm:ss`） | 她写下／吐出的句子 | `说明\角色\高奈利亚.md` + `data\voice\gao_naliya.json` |
| **B 店长的话** | **店长**（对话方） | `you` 气泡里真正打字的那几条、侧栏 6 段旧对话标题、`title`、`question`、`cards_section6` 的 `request` 回显 | 他当时打在输入框里的字 | `说明\角色\店长.md` + `data\voice\dianzhang.json` |
| **C 界面本身** | **终端** | 写给我、完成、设置、新对话、思考中、发送、正在输入…、在线／离开／离线、循环：开、`N 条消息`、最后一条：未读、私密、请求被拒、由我删除 | 控件与系统回执 | 本文第十一节（不是角色，是一套语域） |

**B、C 两类之所以"能改"**：早先按"不能改，改了故事会散"处理，那是把 L2 当成一整片无主的字。现在三个人都给了名字——**有主的字就能按主的口吻写**，故事的骨架（谁说、说什么、什么时候说）不动，只动措辞。

条数实跑清点（`docs/v4/chat_script.json`）：`you` 42 条里真正打字 12 条、其余 30 条是 `click:`/`drag:`/`hover:` 之类的操作注记；`ui` 27 条；`system` 38 条（其中多为**不上屏的清单**，见第二节末）。A 类量级 30 条错误卡 + 约 12 条提示语。

## 四、文件约定：通用规范 ／ 角色卡 ／ 数据表

三层分离，各归各的目录，不混写：

```
二次创作\说明\角色层.md              ← 本文：机制、字段、流程、模板（通用，不含任何角色）
二次创作\说明\角色\<角色id>.md        ← 角色卡：这一个角色的声音（自称、称呼、禁用词、骨架、校准样例、出处）
data\voice\<角色id>.json             ← 机器可读的那张表（代码只读它）
```

- **通用规范不含角色内容**。写进具体句子、具体口癖、具体档案引文，都算放错地方。
- **角色卡不含机制**。不复述三层模型与批次流程，只写"这个人怎么写"。机制改了只改本文，各角色卡不必跟改。
- **`<角色id>` 用小写拉丁 + 下划线**（`gao_naliya`），md 与 json 同名不同后缀，便于脚本对账。
- 新增一个角色 = 加 `角色\<id>.md` + `data\voice\<id>.json` 两份文件，代码与场景零改动。

## 五、数据表字段（`data\voice\<id>.json`）

代码只读这张表，不读人。字段含义与影响面：

| 字段 | 含义 | 影响哪些串 |
|:--|:--|:--|
| `id` / `name` | 标识与显示名 | — |
| `self_ref` | 自称（用不用第一人称、用什么） | A 类全部 |
| `addressee` | 怎么称呼对话者 | A 类全部 |
| `tone` | 情绪刻度分档（`flat` / `holding` / `over`），对应片中不同段落 | 错误卡轻重 |
| `max_len` | 单行字数上限（按面板宽度反算，不是文学偏好） | A 类全部 |
| `punct` | 标点习惯（全角；句末不加句号；不感叹） | A 类全部 |
| `num_rule` | 数字规则（阿拉伯数字／不写约数） | 计数类 |
| `ban` | 禁用词表 | A 类全部 |
| `swap` | 术语替换表 | A 类全部 |
| `skeleton` | 句式骨架（`X：状态`／`还没 Y`／`只剩 N`） | A 类全部 |
| `samples` | 校准样例（3–5 条，评审用，不渲染） | — |

字段缺省时的回退：`punct` 缺省沿用现有全角口径，`max_len` 缺省取现状最长串的实测宽度，`skeleton` 缺省不做自动重排（只走逐条改）。

## 六、角色卡怎么写（通用方法，四条硬要求）

一张角色卡必须能回答四件事，缺一不算合格：

1. **声音从哪来**——给可核的出处（原作档案/官方语音/剧本），不许凭印象。没有出处的形容词一律视为无效。
2. **规则要能判**——每条写作规则必须带判据：什么样的句子算过、什么样算不过。只有形容词（"冷峻""温柔"）的规则不算规则。
3. **校准样例 3–5 条**——覆盖"计数行 / 短提示 / 长句"三档，并注明走了哪条规则。样例是给别人照着写的标尺。
4. **缺口留白**——角色声音的取向（自称、称呼、避讳）属作者判断，卡里必须显式标「待定」，不代拟。

角色卡模板见文末附录。

## 七、迁移批次（一批一验收，不合并）

| 批 | 范围 | 风险 | 备注 |
|:--|:--|:--|:--|
| 0 | 角色卡的四格（`self_ref` / `addressee` / `ban` / `skeleton`）拍板 | 无 | 只定口径，不动片子 |
| 1 | 错误卡：`spread` 14 条 + `first_error` 1 条的标题与正文（30 条） | 中（长句，撞分行） | 最能见人格；**已收口**（`942d2ab`） |
| 2 | 她那一侧的提示语（约 12 条） | 低（短句，只撞字数） | 收益最快；**已做 5 条**（`d926b96`） |
| 3 | C 类终端语域（约 65 条，含不上屏清单） | 低 | 见第十一节；多数判不改 |
| 4 | B 类店长的字（真正打字 12 条 + 侧栏 6 条 + `title`/`question`/卡片回显） | 中 | 见 `说明\角色\店长.md`；改的是措辞，不是剧情 |

**不动**：歌词（L0）、等宽日志行与错误码（L1）。

## 八、每条改完的验收（四步，不能省）

1. `node tools/zh_charset.mjs`——新字进表；`--check` 必须退出 0
2. `node tools/zh_script_doc.mjs`——重生成 `二次创作\文稿\台词中文稿.md`（文档不手抄）
3. `node export/export.mjs --sheet out\_scan\<名>.png --times <该串出现的时间点>`——定点出帧
4. 判据三条：不越框 / 不断成孤字 / 不压邻近元素。任一条不过就回退，不叠第二版

另有两条与角色无关的硬约束：**字数只能减不能加**（固定面板，逐条核 `out\_lib\text_dump.json` 的 `x/y`）；**不能凭空造字**（否则导出报 `[text] glyph outside ... (U+XXXX in sans)`，`中文化.md` 5.2 实测）。

---

## 九、打通之后：给另一个角色适配

1. 复制附录模板成 `说明\角色\<新id>.md`，填四件硬要求
2. 落 `data\voice\<新id>.json`（至少 `self_ref / addressee / ban / skeleton`）
3. 批 2 短提示语按骨架自动重排 → 抽 5 条人工过；批 1 错误卡逐条过
4. 跑第八节四步

**可复用的**：骨架、禁用词、数字规则、字数上限、批次流程、验收脚本。
**救不回来的**：歌词（换角色要整片重排）、八张画板（与角色的形态绑定，`说明\画板配准.md`）。

## 十一、终端语域（C 类）

C 类不是角色，所以规则写在这里，不建角色卡。终端是**窗口自己在说话**：控件名、状态回执、计数。它的口径在 `说明\中文化.md` 第五、六节那套冷腔之上，再收三条：

| # | 规则 | 判据（过／不过） |
|:--|:--|:--|
| C1 | **不出现第一人称**。"我"只属于人，终端写"已删除"不写"由我删除"。 | 出现"我/咱"即不过 |
| C2 | **只写机器能判的事实**，不写人的判断与情绪。能判的是"有没有"（空／无／未读／无载入），不能判的是"她怎么想"（不想说话、难过、舍不得）。 | 出现评价性形容词即不过 |
| C3 | **标签用界面名词，状态用短语**，`标签：状态` 的冒号结构不破（`光标：闪烁`、`窗口：已封闭`、`在线状态：尚无人`）。 | 改成句子（含句号）即不过 |

C 类不追人格，也不做方言化；它的价值在于**衬出另外两个声音**——她越短，店长越口语，终端就越该是干的结构。

另外：`chat_script.json` 的 `system` 里那批 `标签：状态` 的清单串（`剩余部件：4`、`输入框：等待输入`、`运行：无载入`、`光标：闪烁`…）**实际上全都不上屏**——`out\_lib\text_dump.json`（25,769 条上屏文本）里一条都查不到，片上印的是英日志行 `pieces left: N` 一类。这批只做文档一致，不参与出帧核对。真正上屏的 C 类只有：`防护层`、`已记录`、`未定义`、`回答：` / `不同：` 两个标签、以及 `ERR_*` 与代码行。

**复核记录（2026-11-18，67 条全量）**：把 `system`（38 条）与 `settings_rows` 的标签/取值（29 条）逐条过了一遍 C1/C2/C3。

- C1（第一人称）：**0 命中**。
- C2（评价性）：机扫只命中 `输入框：等待输入`，是"等待"里的"等"字误报，不是评价。原先被当成违规的 `思考：无话可答` 对的是英文 `thinking: nothing to answer`，写的是"没有可答内容"，是机器能判的有无，不是人的情绪——据此把 C2 的判据改成"能判有无、不能判情绪"。
- C3（`标签：状态` 结构）：唯一机扫异常是 `回答：6   不同：1`，它本身就是两个 `标签：值` 并排，结构没破。
- 结论：**C 类无违规**，本轮不改字。

**不在 A/B/C 之内的字**：`overlay.js` 的片头免责声明（"本片含有闪烁画面与强光""非官方同人作品…"）与 `meme.js` 的彩蛋（"不要嘲笑我做的视频"）是**作者本人的口吻**，既不属她、也不属店长、也不是终端。这类字永远不许按角色改。

**死 fallback 也要跟**：JS 里 `?? '…'` 兜底的旧文案（`04_pre1.js` 的 `blind`、`10_error.js` 的 `FIRST`）平时不显形，但它是同一个音的第二次录音。改了 JSON 而落下兜底，将来某条路径闪回旧句时，片子里就出现两个版本的她说同一句话。
