## 一、这是什么

Mili - world.execute(me); 的歌词 MV，**确定性渲染器**：画面是 `t` 的纯函数，同一个时间点永远出同一帧。没有关键帧、没有时间线，15 段镜头按小节号和小节内的拍位硬编码在 `src/scenes/`。

- 分辨率虚拟坐标 1920×1080，出片可到 4K60
- 片的起点是**歌曲时间 −5 秒**（闪烁警告页），不是 0。所有导出参数里的 `--start/--end` 都是**歌曲时间**
- 本版本：**中文台词版已完成**——界面/对话/错误文案/警告页/片尾署名全量简体中文，歌词一字未改；1080p60 全片已出（13,017 帧 / 216.95 s），4K60 母版等美术定稿再跑

## 二、怎么跑

```powershell
cd E:\DCIM\doubaoWS\workspace\world-execute-中文版

# 1. 预览（会弹浏览器窗口）
npm run preview            # http://localhost:5173，Ctrl+C 停

# 2. 出单帧验镜（无窗口，最快的验证手段）
node export/export.mjs --sheet out\ka.png --times 25.6 --cols 1 --width 1280 --height 720

# 3. 出一小段（先小后大，别一上来 1080p60 整片）
node export/export.mjs --start 0 --end 5 --width 960 --height 540 --fps 30 --out out\sample.mp4

# 4. 整片
npm run export:preview     # 1080p60
npm run export:4k          # 3840×2160@60

# 5. 改完镜头重出分镜表
npm run storyboard
```

`--sheet` 默认拼成 4 列，**取单帧一定要加 `--cols 1`**，否则会拼成大图，看图和分享都麻烦；单张超过 5 MB 的拼图 `Read` 读不出来，验收固定 1280×720。

## 三、目录地图

| 位置 | 管什么 |
|:--|:--|
| `index.html` + `src/main.js` | 页面入口，预览与导出两种模式共用一套引擎 |
| `src/engine/` | 渲染核心：`draw.js` 字体与绘图、`art.js` 剪影分离、`post.js` 后期、`engine.js` 装配 |
| `src/scenes/` | 15 段镜头，一段一个文件，全按小节硬编码 |
| `src/scenes/cues.js` | 所有不落在拍点上的时间：单词、音节、鼓点，全片唯一出处 |
| `docs/v4/chat_script.json` | **整片台词总闸**：标题、问题、侧栏、设置项、各段对话 |
| `docs/v4/errors.json` | 六类报错文案 |
| `assets/character/` | 八张角色剪影 + `regions.json` 部位表 |
| `data/lyric_timing.json` | 129 行歌词的时间表（**不含歌词文字**），换歌就废 |
| `data/lyrics.json` | 由 `音頻&歌詞/lyrics.txt` + 上表自动生成，本机产物 |
| `config.json` | 配色九个状态、字体、打字速度、安全阈值、导出编码 |
| `二次创作/` | 本工程自己的东西：新素材、中文稿、说明 |

## 四、本机实测（2026-11-16）

| 项 | 值 |
|:--|:--|
| Node / npm | v22.23.2 / 10.9.8 |
| 浏览器 | 只有 **Edge**（没有 Chrome），Playwright 走 `channel: 'msedge'` |
| GPU | RTX 4060 Laptop，ANGLE / D3D11，硬件渲染 |
| 预览渲染耗时 | 0.3–3 ms/帧 @960×540（导出时单帧 1–4 ms） |
| 导出 960×540@30 | **约 30 fps**（1.5 倍实时） |
| 1080p60 全片 | **8.0 fps**，13,017 帧 / 216.95 s / 508.7 MB，约 **27 分钟**（瓶颈是 x264 回写 `send` 67–110 ms/帧，不是渲染） |
| 4K60 | 实测 **3.3 fps** → 全片约 **65–70 分钟**，等美术定稿再跑 |

对比：Linux 容器上软件渲染只有 0.6 fps @1080p60，读帧是瓶颈。本机没有这个问题。

## 五、已知坑（都实测过）

1. **不能双击 `index.html`**。`file://` 下 ES module 被 CORS 挡掉，页面永远停在加载条。必须走本地服务器。
2. **没有 Chrome**。任何 `channel: 'chrome'` 的调用都会失败，要 fallback 到 `msedge`。
3. **`ffmpeg-static` 里没有 Windows 二进制**（这个包是从 Linux 装过来的），靠系统 ffmpeg 4.2.2 顶着（`C:\Users\<user>\AppData\Local\Programs\Python\Python311\Scripts\ffmpeg.exe`）。4.2.2 **编进去了 `h264_nvenc` 但用不了**（`Cannot get the preset configuration: unsupported param (12)`，旧 nvenc API 不认新驱动；本机有 RTX 4060），导出自动落到 `libx264`，属正常。若哪天 PATH 里没有 ffmpeg，就得 `node node_modules/ffmpeg-static/install.js` 重装。
4. **没有 `.venv`**：`npm run check`、`npm run analyze`、`npm run lyrics:retime` 三条脚本写死了 `.venv\Scripts\python`，现在跑不了。要用质检工具（`tools/check_flash.py`、`check_sync.py`、`analyze_audio.py`）得先建虚拟环境装依赖。
5. **歌词有三行对不上参照表**：第 8、9、49 行（0:10.09 / 0:11.10 / 1:19.23）是 `lyrics.txt` 与 `data/lyric_timing.json` 的分词差异，不是故障，但绑在单字上的画面可能差半拍。
6. **`node_modules` 是指向原目录的目录链接**。原目录被移动或删除，这份工程立刻跑不起来。
7. **中文字体三个坑**（换行、字宽、白名单），见 `说明/中文化.md`。

## 六、改东西动哪里

| 想换什么 | 动这里 | 备注 |
|:--|:--|:--|
| 台词、标题、侧栏、设置项 | `docs/v4/chat_script.json` | 一个 JSON 管全片，改完直接出帧看 |
| 报错文案 | `docs/v4/errors.json` | 六类：首次报错、扩散、循环、非法请求、计数、最后一声 |
| 角色剪影 | `assets/character/*.png` + `regions.json` | **三墨色 + alpha 透明**，不是普通插画，见 `素材/角色/README.md`；**换图先跑 `python tools/art_intake.py --src "<收图目录>"`** 归位到基线构图，见 `说明/收图流程.md`；要找"形体"用双生视界 Live2D 库，见 `说明/素材库.md` |
| 配色与情绪线 | `config.json → palettes` | 九个状态，颜色是叙事不是装饰 |
| 字体 | `config.json → fonts` + `src/engine/draw.js` | 中文必须先改引擎，见 `说明/中文化.md` |
| 歌与歌词 | `config.json → paths.audio`、`音頻&歌詞/` | **换歌等于整片重做**，时间表和 90 多处 cue 全部作废 |
